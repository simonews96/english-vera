# claude-api-browser

## Topic
Direct-from-browser Claude API for a BYOK static web app (GitHub Pages): browser access/CORS, streaming, structured outputs, model/latency choice, prompt caching, rate limits, refusals

## Summary
1. Browser calls work: SDK option `dangerouslyAllowBrowser: true` makes `@anthropic-ai/sdk` (npm 0.131.0, dual CJS/ESM exports) send header `anthropic-dangerous-direct-browser-access: true`; a raw fetch with that header + `x-api-key` + `anthropic-version: 2023-06-01` + `content-type: application/json` passes CORS preflight (SDK source verified; CORS behaviour itself only from secondary reports, latest Aug 2026).
2. Streaming: `stream: true` SSE; text arrives as `content_block_delta`/`text_delta`; `message_start.message.usage` has input_tokens, cache_creation_input_tokens, cache_read_input_tokens; `message_delta.usage` is cumulative and carries output_tokens (+ `output_tokens_details.thinking_tokens` only on final message_delta). TS helper: `client.messages.stream(...).on('text', fn)`, `await stream.finalMessage()`.
3. Structured outputs are GA (no beta header): `output_config: {format: {type: "json_schema", schema}}`; supported on Sonnet 5.5, Opus 5.5, Haiku 4.5 (claude-haiku-4-5-20251001). They stream like normal responses (JSON as text_delta chunks of one text block) and work with thinking (grammar does not constrain thinking). First use of a new schema adds compile latency; grammar cached 24h from last use.
4. Lowest-latency config: Haiku 4.5 (thinking off unless `{type:"enabled",budget_tokens>=1024}`; no effort param; "Fastest") or Sonnet 5.5 with `thinking: {type: "between_tools"}` + `output_config.effort: "low"|"medium"` (`disabled` is a 400; without tools the response is text only). Opus 5.5 cannot turn thinking off at any effort (default effort medium) so it is not a low-latency choice.
5. Prices/MTok: Sonnet 5.5 $2/$10 (cache write $2.50 5m, $4 1h, read $0.20); Haiku 4.5 $1/$5 ($1.25/$2/$0.10); Opus 5.5 $4/$20 ($5/$8/$0.20). No newer Haiku exists; Haiku 4.5 is Active, retirement "not sooner than Oct 15 2026" with no announced retirement as of 2026-10-02.
6. Caching: min cacheable prefix 512 tokens on Sonnet 5.5/Opus 5.5 but 4,096 on Haiku 4.5; TTL 5m default or `ttl: "1h"` (2x write); top-level request `cache_control: {type: "ephemeral"}` = automatic caching (moves breakpoint to last cacheable block). Changing effort/thinking config between turns invalidates cache.
7. Rate limits: tiers are now Start/Build/Scale/Custom (docs no longer say "Tier 1"); Start = 1,000 RPM, 2,000,000 ITPM, 400,000 OTPM per model, cache reads excluded from ITPM; new orgs may start in an unpublished lower "Evaluation tier". 6 short turns/min is negligible. Spend: tier cap $500/month on Start; user can set a lower limit at Settings > Billing (then HTTP 400 invalid_request_error "You have reached your specified API usage limits"); per-workspace spend/rate limits exist (not Default Workspace); no per-key spend limit, but keys can be workspace-scoped and given an expiration.
8. Refusals: Sonnet 5.5 (and Opus 5.5) run classifiers and can return HTTP 200 with `stop_reason: "refusal"` + `stop_details.category` (cyber, bio, frontier_llm, reasoning_extraction, general_harms); Haiku 4.5 is not listed among classifier models. Docs: check stop_reason before reading content, discard partial stream output, rephrase; avoid schema fields asking for the model's reasoning (reasoning_extraction); optional `fallbacks: "default"` + beta `server-side-fallback-2026-07-01` on `client.beta.messages`.
9. Sonnet 5.5 gotchas: non-default temperature/top_p/top_k → 400; assistant prefill → 400; forced tool_choice any/tool → 400; tokenizer ~30% more tokens than Haiku 4.5.

## Recommendations
- Call api.anthropic.com directly from the page: either `new Anthropic({ apiKey, dangerouslyAllowBrowser: true })` (SDK 0.131.0, ESM-bundleable by Vite) or a raw `fetch` with headers x-api-key, anthropic-version: 2023-06-01, content-type: application/json, anthropic-dangerous-direct-browser-access: true. Raw fetch avoids shipping the SDK and gives full control of the SSE loop; keep the key in localStorage only (BYOK) and tell users to create a dedicated personal key with an expiration and workspace scope.
- For minimum latency pick one of two configurations and A/B them: (a) claude-haiku-4-5 with no `thinking` field (thinking off by default, no effort param accepted, fastest tier; ~0.6 s TTFT per third-party data); (b) claude-sonnet-5-5 with `thinking: {type: "between_tools"}` and `output_config: {effort: "low"}` (or medium) — no up-front thinking, text-only response when no tools are passed. Do not use Opus 5.5 for the per-turn tutor path: thinking cannot be disabled and default effort is medium.
- Always stream (`stream: true`); render `text_delta` as it arrives (for the voice tutor, feed TTS sentence-by-sentence) and read `message_delta.usage` (cumulative) plus `message_start.message.usage.cache_read_input_tokens` to show cost. Handle `event: error` (overloaded_error) and `message_delta.delta.stop_reason === "refusal"` / "max_tokens".
- Use structured outputs via `output_config.format = {type: "json_schema", schema}` (GA, works on Haiku 4.5 and Sonnet 5.5, streams as text_delta chunks). Put the tutor's spoken reply as the FIRST required string property so you can start speaking before the JSON closes (required properties are emitted first); use a tolerant/partial JSON parser on the accumulating text; set additionalProperties:false everywhere, avoid min/max/pattern/recursion, and never name a field 'reasoning'/'thinking' (reasoning_extraction refusal). Keep exactly one stable schema and warm it with a tiny request at app start (first use compiles the grammar; cached 24 h).
- Prompt caching: send top-level `cache_control: {type: "ephemeral"}` (automatic) and additionally an explicit breakpoint on the system prompt block. On Sonnet 5.5 the system prompt must be >=512 tokens to cache; on Haiku 4.5 it must be >=4,096 tokens, so a short tutor prompt on Haiku will never cache (fine at $1/MTok). Hold thinking config and effort constant for the whole session (changes invalidate the cache) and keep anything time-varying after the breakpoint.
- Rate limits are not a concern: Start tier gives 1,000 RPM / 2M ITPM / 400K OTPM per model; ~6 turns/min with a few-thousand-token context is far below even plausible Evaluation-tier limits. Still implement one retry on 429 honoring `retry-after`, and surface `enforced_spend_limit_reached` (429, no retry-after) and the HTTP 400 'You have reached your specified API usage limits' message to the user as 'raise your limit in Settings > Billing'.
- Tell users how to cap spend: Console Settings > Billing > Spend limits (org-wide, below the $500 Start cap), or create a non-default workspace with its own monthly spend limit and scope the key to it; keys themselves have no spend limit, but set an expiration (e.g. 30 days).
- On Sonnet 5.5 never send temperature/top_p/top_k, prefill, or forced tool_choice (all 400). If you must keep a tiny chance of refusal from blocking a lesson, catch stop_reason refusal and re-send the turn to Haiku 4.5 client-side (no classifiers listed for it); the server-side `fallbacks: "default"` beta only covers cyber/frontier_llm and requires the beta messages endpoint.
- Plan for Haiku 4.5's lifecycle: it is Active today (2026-10-02) with retirement 'not sooner than 2026-10-15' and no announcement yet; make the model ID a user-visible setting so a future deprecation needs no redeploy, and note Sonnet 5.5 uses a tokenizer that produces ~30% more tokens than Haiku 4.5 for the same text (budget max_tokens accordingly).

## Critical claims + verdicts
### C1: Browser-origin requests to https://api.anthropic.com/v1/messages succeed (CORS preflight passes) when the request carries `anthropic-dangerous-direct-browser-access: true`; the SDK sets this header automatically when `dangerouslyAllowBrowser: true`.
  WHY: The entire static-site/BYOK design has no backend; if Anthropic ever withdrew browser CORS support the app would need a proxy. Header verified in SDK source; CORS behaviour verified only via third-party reports (latest Aug 2026), not platform docs.
  VERDICT: confirmed
  EVIDENCE: LIVE TESTS (curl against https://api.anthropic.com, 2026-10-02 14:59-15:00 UTC, Origin: https://example.github.io) [verified]:
- OPTIONS /v1/messages, Access-Control-Request-Headers includes anthropic-dangerous-direct-browser-access → HTTP 200, `access-control-allow-origin: *`, `access-control-allow-methods: DELETE, GET, HEAD, OPTIONS, PATCH, POST, PUT`, `access-control-allow-headers: <echo of requested headers>` (also echoes anthropic-beta and all x-stainless-* headers the SDK sends), `access-control-max-age: 600`, `access-control-allow-credentials: true`, `vary: Origin, Access-Control-Request-Headers`.
- Same OPTIONS WITHOUT that header in Access-Control-Request-Headers → HTTP 400, body "Disallowed CORS origin", NO access-control-allow-origin → browser preflight fails. OPTIONS with no Access-Control-Request-Headers at all → 400.
- POST /v1/messages with header `true` (invalid key) → 401 with `access-control-allow-origin: *`, `access-control-expose-headers: *`, `vary: ... anthropic-dangerous-direct-browser-access` (server explicitly keys CORS on this header). POST without header → 401 with NO CORS headers. Header value `false` or empty → still gets ACAO:* (presence check). Also works with `Origin: null`, with `Authorization: Bearer`, on `/v1/messages?beta=true`, `/v1/messages/count_tokens`, and `GET /v1/models`.
- Caveat: ACAO `*` + allow-credentials true → browser rejects if fetch uses credentials:'include'; SDK default fetch is non-credentialed, fine. expose-headers `*` means request-id and rate-limit headers are readable from JS.

SDK SOURCE [verified, two access paths]: raw client.ts and GitHub code search of anthropics/anthropic-sdk-typescript src/client.ts: `...(this._options.dangerouslyAllowBrowser ? { 'anthropic-dangerous-direct-browser-access': 'true' } : undefined)`; constructor throws AnthropicError "It looks like you're running in a browser-like environment... set the `dangerouslyAllowBrowser` option to `true`" when isRunningInBrowser() and option unset. ### C2: Structured outputs (`output_config.format`, GA, no beta header) are supported on Haiku 4.5 and Sonnet 5.5 and stream as ordinary `text_delta` chunks of one text block, compatible with thinking being on or off.
  WHY: The tutor needs typed JSON (reply, corrections, language tags) while still streaming to TTS; if streaming did not work with structured outputs, the design would need two calls or prompt-only JSON.
  VERDICT: confirmed
  EVIDENCE: CONFIRMED (core claim), with nuances below. All sources read 2026-10-02.

1. GA / no beta header — verified. structured-outputs.md frontmatter: `status: ga`; "Migrating from the beta" section: "The `output_format` parameter has moved to `output_config.format`, and beta headers are no longer required... Independent: release-notes/overview.md, Jan 29, 2026 entry: "Structured outputs are out of beta on the Claude API for Claude Sonnet 4.5, Claude Opus 4.5, and Claude Haiku 4.5 ... no beta header required. TS SDK example `structured-outputs-streaming.ts`: `client.messages.stream({... output_config: { format: ... } })`, then `for await (const event of stream) { if (event.type === 'content_block_delta' && event.delta.type === 'text_delta') process.stdout.write(event.delta.text) }`, then `stream.finalMessage().parsed_output`. Python SDK `messages.py` `def stream(...)` accepts `output_config` and `output_format` (type), merging into `output_config.format`. 4. "One text block" — likely, not explicitly guaranteed. SDK parsers iterate every text block: TS `src/lib/parser.ts` parses each `text` block and sets message `parsed_output` to the FIRST parsed text block; Python `_parse/_response.py` parses each text block. C# docs: "parses each text block back into it". No doc sentence guarantees exactly one text block; in practice (no tools) response = [optional thinking block] + text block.

5. Thinking compatibility — verified. structured-outputs.md Tip: "Grammars apply only to Claude's direct output, not to tool use calls, tool results, or thinking tags (when using thinking). Grammar state resets between sections, allowing Claude to think freely while still producing structured output in the final response." "Incompatible with" list contains only Citations (400) and Message Prefilling — NOT thinking. thinking.md limits section lists prefill, forced tool use, sampling params as incompatibilities, not structured outputs; it actually recommends structured outputs as the replacement for forced tool use on Sonnet 5.5/Opus 5.5.

NUANCES for the design:
- Sonnet 5.5: thinking cannot be fully off. `thinking: {type: "disabled"}` → 400; lowest is `thinking: {type: "between_tools"}` (effort low/medium/high only; xhigh/max → 400), which "without tools, the response contains only text". Default = adaptive with `display: "omitted"`, so the stream is: thinking block (`thinking_delta` with empty string + `signature_delta`) then text block with `text_delta`s. `display: "omitted"` gives fastest time-to-first-text. `type: "enabled"`+`budget_tokens` → 400 on Sonnet 5.5.
- Haiku 4.5: thinking off by default; `type: "adaptive"` → 400; use `{type:"enabled", budget_tokens:N}`; `effort` not supported.
- Sonnet 5.5 rejects non-default `temperature`/`top_p`/`top_k` (400).
- Refusals: `stop_reason: "refusal"` with HTTP 200, output may not match schema. A `reasoning`/`thinking`/`trace` field in the JSON schema can trigger `stop_details.category: "reasoning_extraction"` on Sonnet 5.5 (listed), billed even if no output. `stop_reason: "max_tokens"` → truncated/invalid JSON.
- Prompt caching: changing `output_config.format` schema invalidates cache; schema injects an extra system prompt; first use of a schema adds grammar-compile latency (cached 24h).
- Schema limits: no `minLength`/`maxLength`/`minimum`/`maximum`, no recursive schemas, `additionalProperties` must be false, max 24 optional params and 16 union-typed params; enum capitalization not guaranteed; required properties are emitted before optional ones.
- Prefill incompatible with JSON outputs; Citations → 400.
- Haiku 4.5 retirement "Not sooner than October 15, 2026" (13 days from today) — model-choice risk.
