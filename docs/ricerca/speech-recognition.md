# speech-recognition

## Topic
Web Speech API SpeechRecognition (2026) for a bilingual EN/IT voice tutor across Chrome/Edge desktop, Chrome Android, Safari iOS, Chrome iOS, Firefox

## Summary
Desktop Chrome/Edge: solid. Cloud (Google/Azure) by default; Chrome 139+ offers on-device via SpeechRecognition.available()/install()/processLocally (17 langs incl. en-US and it-IT; AVX needed on x86; install() needs a user gesture). Continuous sessions end on their own: Chromium ends after 15 s of silence (continuous) and fires "no-speech" after 8 s with no speech at start; plan on an onend restart loop.
Chrome Android: continuous is effectively ignored (Chromium code terminates the session after the first onResults, documented in source; MDN BCD: "can be set, but has no effect"); every restart triggers the Android OS beep; background/hidden page kills the session permanently; no on-device Web Speech (available() returns "unavailable", install() false) so audio always goes to Google's recognizer.
Safari iOS/iPadOS: works only in a Safari tab. Not in Home Screen (standalone) web apps nor in WKWebView (so Chrome/Firefox/in-app browsers on iOS expose webkitSpeechRecognition but it does nothing). WebKit uses Apple's SFSpeechRecognizer with requiresOnDeviceRecognition when the locale supports it (otherwise audio goes to Apple), 1-hour cap, interim results supported but field reports (2021-2026) show duplicated/re-delivered words, isFinal never true in continuous mode, throttled interims; WebKit re-prompts for mic/speech permission on each main-document navigation unless the site has a persistent "Allow".
Firefox: disabled by default (media.webspeech.recognition.enable=false), Nightly-only, online Mozilla endpoint, 10 s max listening. Not viable.
Language switch: lang is bound at session start on every engine (Chrome sends lang= in the upstream request; WebKit creates the SFSpeechRecognizer with the locale); must abort()/start() a new session.
Phone-first loop verdict: viable on Android only as a per-utterance restart loop with beeps; viable on iOS only inside Safari proper with aggressive dedupe/timeouts; a MediaRecorder + server STT fallback is mandatory for iOS standalone PWA, Chrome iOS, Firefox.

## Recommendations
- Design the tutor loop as strict half-duplex: abort() recognition before speechSynthesis.speak(), restart recognition only in utterance.onend (+ ~300 ms), never overlap mic and TTS (echo, iOS audio-session conflicts, Android session termination).
- Per-platform listening strategy: desktop Chrome/Edge -> continuous=true, interimResults=true, restart in onend (expect an end after 15 s silence; 'no-speech' after 8 s of initial silence); Android Chrome -> continuous=false, one utterance per start(), restart in onend with a short debounce and accept the OS beep (or use MediaRecorder + server STT to avoid it); iOS Safari tab -> continuous=false one-phrase sessions, dedupe repeated n-grams, treat 'no interim change for ~750 ms' as end-of-utterance, hard timeout per session.
- Language switching (EN<->IT): never mutate lang on a live session; abort() the current instance, create a fresh SpeechRecognition with the new lang, start() it; keep lang tags canonical (en-US, it-IT) because both Chrome's on-device packs and Safari's locale availability are matched on exact tags.
- Feature detection on iOS must be behavioral: do not trust 'webkitSpeechRecognition' in window. Detect standalone mode (navigator.standalone / display-mode: standalone) and WKWebView (Chrome/Firefox/in-app browsers) and route those to a MediaRecorder + server-side STT fallback; also start a watchdog: if no onstart/onaudiostart within ~2-3 s or an error fires, fall back.
- Privacy/on-device: on desktop Chrome call SpeechRecognition.available({langs:['en-US','it-IT'], processLocally:true}); if 'downloadable', call install() from a click handler; set processLocally=true only when 'available'; otherwise fall back to cloud and disclose it. On Android there is no on-device option (audio goes to Google); on Safari on-device is automatic when supported and cannot be forced - disclose 'may be sent to Apple'.
- Error handling map: no-speech -> silent restart (count and back off); aborted -> restart only if not caused by our own abort(); audio-capture -> prompt to check mic/Bluetooth route; not-allowed -> stop loop, show permission instructions (iOS: AA > Website Settings > Microphone: Allow); service-not-allowed -> switch to server STT fallback; network -> retry with exponential backoff (1 s, 2 s, 4 s, cap 5 attempts) then fallback; language-not-supported -> fallback language tag / server STT.
- Keep the app a single page without full navigations during a lesson: WebKit clears the speech/mic grant on main-document change, so every full page load re-prompts in Safari; Chrome Android terminates sessions when the page is hidden, so pause the loop on visibilitychange and require a tap to resume.
- Text post-processing: assume no automatic punctuation/capitalization from Chrome cloud or Safari; numbers may arrive as digits (Chrome/Safari formattedString) - normalize before grading; ignore alternative ordering and pick the max-confidence alternative; keep maxAlternatives small (1-3) because Safari ignores more than it can supply and Android gives only ordered results.
- Budget restarts: cap continuous-mode restarts (e.g. 10/min) and stop after N consecutive 'no-speech' errors to avoid Google rate limiting and battery drain; log onend reasons to tune timeouts.
- Build the server-STT fallback path (MediaRecorder -> upload -> STT) from day one; it is the only path that works in iOS standalone PWAs, Chrome iOS, Firefox, and in Brave/Electron builds where cloud Web Speech returns 'network'.
