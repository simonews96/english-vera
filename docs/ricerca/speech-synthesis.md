# speech-synthesis

## Topic
Web Speech API speechSynthesis (2026) for a bilingual it-IT / en-GB|en-US tutor voice ("Vera") on Chrome desktop, Edge desktop, Chrome Android, Safari iOS: voice inventory, voiceschanged, boundary events, known bugs, rate/pitch, and cloud-TTS upgrade path

## Summary
1. Chrome desktop ships 19 remote "Google …" voices (manifest declares only start/end/error events; remote=true → localService=false): "Google UK English Female" (en-GB), "Google US English" (en-US, female), "Google italiano" (it-IT, female). They NEVER fire boundary events and Readium's Oct-2026 voice data still flags the >14 s cutoff bug for them.
2. Chrome's OS voices do fire word boundaries: Windows SAPI (TTS_EVENT_WORD+SENTENCE: "Microsoft Hazel/Susan - English (Great Britain)", "Microsoft Zira - English (United States)", "Microsoft Elsa - Italian (Italy)") and macOS AVSpeech voices (Kate/Serena/Samantha/Ava, Alice/Federica/Emma/Paola; Chrome on macOS lists Enhanced/Premium variants, Safari does not).
3. Edge desktop: best quality is "Microsoft Sonia Online (Natural) - English (United Kingdom)" + "Microsoft Elsa Online (Natural) - Italian (Italy)" (also Libby, Isabella, Ava/Emma/Jenny/Aria US); they are remote and 2026 reports say they emit no usable boundary events; Edge 150 had a "Microsoft undefined Online (Natural) - undefined" naming bug.
4. Chrome Android (verified in Chromium source): voice names are locale display names ("English United Kingdom", "Italian Italy", localized to the phone's UI language), lang uses underscores (en_GB, it_IT), selection is by language only (engine default voice, gender not choosable), pause()==stop, resume() no-op, no boundary events.
5. Safari/iOS (verified in WebKit): getVoices() is synchronous and cached; speak() silently no-ops outside a user gesture until unlocked; only isSystemVoice voices are listed (downloaded Enhanced/Premium/Siri hidden); word boundaries fire via AVSpeechSynthesizer; cancel() fires error('canceled') not end; utterance.lang is ignored unless utterance.voice is set.
6. Chrome/Edge (verified in Blink): first getVoices() is empty until the browser sends the list, then voiceschanged; cancel() fires error 'interrupted' (current) / 'canceled' (queued), never end.
7. Rate 0.1–10 / pitch 0–2 (default 1); WebKit maps rate onto AVSpeech (<1 multiplies default rate, >1 interpolates to max); Google voices pass rate/pitch (÷2) to Google; rate cannot change mid-utterance (cancel+respeak). Use 0.8 for "più lento", keep pitch 1.0.
8. Cloud: Google TTS REST allows browser calls with ?key= (CORS preflight verified: ACAO echoed) and returns SSML <mark> timepoints (enableTimePointing:["SSML_MARK"]); Azure JS SDK talks WebSocket (no CORS) and gives wordBoundary(audioOffset/textOffset/wordLength) automatically; ElevenLabs has /with-timestamps (character alignment) and reportedly CORS *; OpenAI /v1/audio/speech (gpt-4o-mini-tts, tts-1[-hd], stream_format sse|audio) has no timestamps.
9. Rough prices (secondary): Google Standard $4/1M chars, Neural2 $16, Chirp3-HD $30, Studio $160; Azure neural $16, HD $22 (Mar-2026); ElevenLabs ≈$50 (Flash) / $100 (v2/v3) per 1M; OpenAI gpt-4o-mini-tts ≈$0.015/min (≈$12/1M audio tokens), tts-1 $15/1M chars, tts-1-hd $30/1M.
10. Design consequence: boundary-driven animation is only available with local OS voices on Windows/macOS (Chrome) and on Safari; everywhere else (Google voices, Edge Natural, Android) the animation must be time-estimated and re-seeded per sentence chunk.

## Recommendations
- Define the engine interface around capabilities, not events: speak(chunk, {lang, voiceId, rate}) → Promise settled on end OR error('interrupted'|'canceled'); expose engine.capabilities = {wordBoundary: boolean, selectableVoice: boolean, pauseResume: boolean, needsGesture: boolean, maxChunkSeconds}. Treat every error event as terminal (Chrome and Safari both report cancel() as an error, never end).
- Voice resolution per platform, ranked by name substring then lang (normalize lang with replace('_','-') and compare case-insensitively on the first 5 chars): en-GB female → ['Microsoft Sonia Online (Natural)', 'Microsoft Libby Online (Natural)', 'Serena', 'Kate', 'Stephanie', 'Google UK English Female', 'Microsoft Hazel', 'Microsoft Susan', 'Martha']; en-US female fallback → ['Microsoft AvaMultilingual', 'Microsoft EmmaMultilingual', 'Microsoft Jenny', 'Microsoft Aria', 'Ava', 'Samantha', 'Zoe', 'Allison', 'Google US English', 'Microsoft Zira']; it-IT female → ['Microsoft Elsa Online (Natural)', 'Microsoft Isabella Online (Natural)', 'Federica', 'Emma', 'Alice', 'Paola', 'Google italiano', 'Microsoft Elsa']; exclude child voices (Ana, Maisie, Joelle, Pierina), Eloquence (Eddy, Flo, Grandma, Grandpa, Reed, Rocko, Sandy, Shelley), novelty voices, and names containing 'undefined'. Final fallback: first voice whose lang starts with the requested language, then any voice whose lang starts with 'en'/'it'.
- Keep Vera coherent across languages by choosing both voices from the same family in this priority: Edge Natural (Sonia + Elsa) > Apple (Kate/Serena or Samantha + Alice/Federica) > Google network (UK English Female + italiano) > Windows local (Hazel/Susan + Elsa). On Chrome Android accept that only the engine default per language is available (match by lang en-GB → en_GB, it-IT → it_IT; fall back en_US).
- When boundary-driven animation matters more than voice quality on Chrome/Edge desktop, prefer a local voice (voice.localService === true) and verify at runtime: speak a 3-word probe and record whether a 'boundary' arrives within ~1.5 s; cache the result per voiceURI. If no boundaries, drive the animation from an estimated chars/sec that is re-seeded from each chunk's measured start→end duration (per-chunk bounded drift).
- Chunk every utterance on sentence boundaries (. ! ? ; : and line breaks), cap ≈160-200 chars / ≈10 s of audio, keep at most two utterances queued; this sidesteps the Chrome Google-voice cutoff without the pause()/resume() timer hack (which breaks on Android). Never try to change rate mid-utterance: cancel() and re-speak the current chunk.
- Voice loading: call getVoices() immediately; if empty, await 'voiceschanged' with a 1.5-2 s timeout and re-read; re-run the resolver on every later 'voiceschanged' (Edge adds Natural voices late). Persist the chosen voiceURI per language in localStorage and re-validate on load.
- iOS/Safari: unlock speech in the first touchend/click/keydown handler by speaking '.' with volume 0.01 and rate 10 (never volume 0 or empty text), call cancel() first to clear a wedged queue, always set utterance.voice (lang alone is ignored), and on visibilitychange re-speak the current chunk if speech stopped while hidden. Gate 'auto-play' features behind an explicit tap on iOS.
- Rate presets: normal 1.0, 'ripeti più lento' 0.8 (floor 0.7), 'ancora più lento' 0.7; keep pitch 1.0 for identity; keep all values within 0.5–2 for Safari safety and re-speak from the current chunk when the preset changes. Test audibility per family: AVSpeech (WebKit) compresses the <1 range, SAPI and Google scale more linearly.
- Cloud upgrade path, in order of fit: (1) Azure Speech JS SDK — browser-direct via WebSocket, no CORS, native wordBoundary + viseme events, en-GB-SoniaNeural / it-IT-ElsaNeural are the same voices as Edge; (2) Google Cloud TTS REST with ?key= (CORS verified) and SSML <mark> per word → timepoints; (3) ElevenLabs /with-timestamps or websocket alignment for top quality; (4) OpenAI gpt-4o-mini-tts only if timing is not required. Implement the adapter as fetch→ArrayBuffer→AudioContext/HTMLAudioElement with a timing track [{charIndex, timeSeconds}] so the animation layer is engine-agnostic.
- Budget guardrail for a user-provided key: a 10-minute lesson ≈ 9-10k characters ≈ $0.04 (Google Standard), $0.15 (Google Neural2 / Azure neural), $0.30 (Chirp3-HD), $0.5-1 (ElevenLabs), ~$0.15 (OpenAI mini-tts); cache synthesized audio per (text, voice, rate) in IndexedDB.

(1) CHROME/EDGE/CHROME-ANDROID cancel(): the CURRENT utterance gets 'error' with error='interrupted' (async, after cancel() returns); 'end' is fired only for kNoError. BUT utterances queued by the same page and not yet started get NO event at all (neither 'error' nor 'end'): Blink only hands the front utterance to the browser (speak() calls StartSpeakingImmediately only when queue size==1) and cancel() is literally `utterance_queue_.clear(); mojom_synthesis->Cancel();` with no event dispatch. error='canceled' exists (TTS_EVENT_CANCELLED -> kCancelled) but is reachable only for an utterance already sitting in the browser-side TtsController queue, i.e. when something else (another tab/frame/extension, or a paused controller) was speaking. Chrome fired plain 'end' on cancel before Nov 4 2022 (commit f6a5e23, crbug 1365948, Cr-Commit-Position 1067390; Chrome ~109/110 - version mapping likely, not verified).
(2) SAFARI/WEBKIT cancel(): fires 'error' with error='canceled' on BOTH the current utterance (spec says 'interrupted'; WebKit deviates) and every queued utterance, SYNCHRONOUSLY inside the cancel() call (SpeechSynthesis::cancel -> speakingErrorOccurred -> handleSpeakingCompleted(.., true) -> SpeechSynthesisErrorCode::Canceled; layout test expects "u1: start / u1: error (canceled)"). "Never an 'end'" has a verified source-level race in WebKit2 (real Safari): WebPageProxy::speechSynthesisCancel() only calls synthesizer->cancel() and does NOT clear speakingFinishedCompletionHandler; the Cocoa delegate maps didCancelSpeechUtterance -> didFinishSpeaking -> stored handler -> identity-less WebProcess reply -> SpeechSynthesis::didFinishSpeaking() which applies 'end' to WHATEVER utterance is current. If JS calls speak(next) right after cancel(), next can receive a spurious 'end' (timing-dependent). Code-verified hazard; field reports not re-verified today.
(3) VOICES: Chrome - verified: constructor binds nothing; getVoices() lazily binds mojo + AddVoiceListObserver and returns the (empty) cached list; OnSetVoiceList arrives asynchronously and ALWAYS dispatches 'voiceschanged' (even with an empty list; on Android GetVoices returns empty until the Java TTS engine is initialized, then VoicesChanged fires a second 'voiceschanged'). Caveat: 'voiceschanged' is only subscribed after some call hits TryEnsureMojomSynthesis (getVoices/speak/cancel/pause/resume); setting onvoiceschanged alone never triggers it. Safari - OUTDATED: since WebKit commit 0845cdb (2026-01-15, "PlatformSpeechSynthesizer::initializeVoiceList() should not block", bugs.webkit.org 304944, rdar://164447645) the Cocoa voice list is fetched asynchronously via +[AVSpeechSynthesisVoice speechVoicesIncludingSuperCompactWithCompletionHandler:] on OS >= 26.3 (code comment: "Remove this once 26.3 is the minimum OS version supported by Safari"); getVoices() is still a synchronous (sync-IPC) call but the FIRST result can be EMPTY and is cached until 'voiceschanged' fires (new layout test speech-synthesis-empty-initial-voice-list.html: "the voice list can initially be empty and populated after voiceschanged event"; voices-non-mock.html updated with a timeout fallback). On older OS (< 26.3) or older Safari the synchronous populated behaviour remains. Exact Safari version shipping this: likely 26.4+ (not verified). Net: voice bootstrapping must treat ALL four targets as async (empty-first + voiceschanged), and must not wait for any event on page-queued utterances after cancel() on Chromium.
