# CLAUDE.md — Vera, tutor vocale di inglese

Questo file è la memoria del progetto tra una sessione e l'altra. Ogni sessione riparte da zero: leggilo per intero prima di fare qualsiasi cosa, e aggiornalo prima di chiudere (sezioni "Stato" e "Registro delle decisioni").

## Cos'è Vera

Un tutor vocale di inglese personale per un utente italiano principiante assoluto, obiettivo: cavarsela a voce in viaggio in 6 mesi con ~45 minuti al giorno in sessioni da 5-10 minuti, da PC (Chrome/Edge) e da telefono con auricolari. App statica su GitHub Pages, installabile (PWA), senza server: il cervello è l'API di Claude chiamata dal browser con la chiave dell'utente (salvata solo sul dispositivo); la voce usa le API del browser dietro un'interfaccia sostituibile. L'identità visiva è "Vera al telaio": il corpo di Vera è una stoffa fatta delle frasi inglesi che l'utente ha detto correttamente.

Il piano completo, con le alternative scartate, è in `docs/PIANO.md` (versione 2, già passata da una critica avversariale). Gli appunti di ricerca con fonti e livelli di confidenza sono in `docs/ricerca/`: prima di decidere su un punto tecnico leggere la sezione "Critical claims + verdicts" del file relativo, che contiene le correzioni.

## Come lavorare qui

- **Lingua.** Rispondere sempre in italiano all'utente. Codice, identificatori e commenti in inglese; testi dell'interfaccia in italiano (con le parti inglesi dove sono contenuto didattico).
- **Branch.** Sviluppo su `claude/vera-english-tutor-0psgm6`; commit con messaggi chiari; push con `git push -u origin <branch>`. Mai pull request senza richiesta esplicita. Il deploy su Pages parte da `main` (o dal branch di lavoro se l'utente lo autorizza nell'ambiente `github-pages`).
- **Separazione.** La logica (turni, memoria, ripetizione, parsing della risposta strutturata, costi, pacing, fasi di sessione) vive in `src/core/` senza DOM e senza voce, ed è coperta da test Vitest. La voce sta dietro `SpeechInput`/`SpeechOutput` in `src/voice/`. Esiste sempre una modalità solo testo.
- **Prima di consegnare.** `npm run check` (typecheck + Biome + Vitest + build) verde; `npm run test:e2e` (Playwright con il Chromium headless locale) fa un giro completo in modalità testo con API finta e salva screenshot (chiaro, scuro, movimento ridotto) che vanno guardati. Test che export e sync non contengano segreti e che `dist/index.html` non abbia script inline. Non si pubblica nulla di rosso.
- **Fine sessione.** Aggiornare questo file (stato, decisioni, cosa funziona, cosa non è stato verificato, cosa resta all'utente) e dirlo all'utente nel messaggio finale.
- **Verifica, non memoria.** Per l'API di Claude seguire la documentazione ufficiale (modelli, parametri); per i browser, i comportamenti verificati in `docs/ricerca/`. Niente date nei model ID.
- **Sicurezza.** La chiave API e il token GitHub stanno solo nel browser dell'utente: mai nel repository, mai in log, mai in URL, mai in export o payload di sync. L'origine `simonews96.github.io` è condivisa con ogni altro sito Pages dell'account: l'utente ne è avvisato. CSP via `<meta>` con `connect-src` limitato ad `api.anthropic.com` e `api.github.com`, nessuno script inline o esterno. Filtro che oscura `sk-ant-…` e `github_pat_…` in ogni messaggio salvato o copiato.

## Convenzioni tecniche (decise, da rispettare quando si scrive codice)

- **Stack.** Vite 8 + TypeScript 7 strict, senza framework UI (macchina a stati esplicita, `data-state` sulla radice, CSS derivato). Vitest 5, Playwright 1.63, Biome, vite-plugin-pwa 1.3, `@anthropic-ai/sdk` 0.131, `ts-fsrs` 5.x. Nessun'altra dipendenza di runtime senza motivo scritto qui. Comandi: `npm run dev`, `npm run check`, `npm run test:e2e`.
- **Claude.** SDK con `dangerouslyAllowBrowser: true` e `maxRetries: 0` (politica di retry nostra, tabella in `docs/PIANO.md` §1.1). Preset per modello in `src/core/prompt/`: Sonnet 5.5 = `thinking: { type: "between_tools" }` + `effort: "low"` fissi per tutta la sessione; Haiku 4.5 = nessun `thinking`, nessun `effort`; Opus 5.5 = `thinking` omesso, `effort: "low"`; ID sconosciuto = nessun parametro di ragionamento. Mai `temperature`, prefill o `tool_choice` forzato. Streaming sempre; structured outputs via `output_config.format` (schema con `additionalProperties: false`, `segments` per primo, enum maiuscoli normalizzati dall'app, nessun campo `reasoning`/`thinking`, una versione per traguardo, riscaldamento all'avvio); `max_tokens` ≈ 1.536. **Cache:** system = blocco stabile con `cache_control`; secondo breakpoint sull'ultimo messaggio della storia (come blocco di testo con `cache_control`); la scheda dello studente viaggia DENTRO l'ultimo messaggio utente (`buildUserMessage(card, testo, help)`, tag `<learner_card>` / `<learner_says>`), mai prima della storia; storia append-only dentro la sessione, mai finestra scorrevole; nei turni assistente della storia solo il testo dei `segments`, nei turni utente il testo nudo. Usage reale (inclusa scrittura cache) per il contatore; il barge-in non abortisce mai la richiesta. Su `refusal`/`max_tokens` il JSON parziale non viene né validato né persistito. Convalida chiave con `GET /v1/models`.
- **Voce.** `speak()` restituisce `"ended" | "cancelled" | "error"`: una sola utterance nel browser alla volta; `cancel()` risolve tutte le promesse in volo con un token di generazione senza aspettare eventi (su Chromium le utterance accodate non ricevono alcun evento; `cancel()` non produce mai `end`); watchdog per utterance; riferimento tenuto vivo; su WebKit lo `speak()` dopo `cancel()` è rinviato a un macrotask e un `end` prima di `start` è ignorato. Bootstrap voci asincrono ovunque (`getVoices()` subito, `voiceschanged` con timeout 2 s, risoluzione ripetuta a ogni evento, `voiceURI` persistito); risoluzione a cascata con ultimo gradino obbligatorio. Su Android sempre `utterance.lang` e `utterance.voice`, mai `pause()`. Sblocco iOS nel gestore sincrono del tocco, prima di ogni `await`: `cancel()` + `speak(".")` con `volume` 0,01 e `rate` 10. Half-duplex rigoroso con flag `ownAbort`; nuovo `SpeechRecognition` a ogni cambio lingua e, su iOS, dopo ogni frase di Vera; watchdog su ogni `start()` (3 s); tetto ai riavvii; solo `results[resultIndex…]` e solo `isFinal`; mappa errori in `docs/PIANO.md` §1.2. Nessun secondo flusso microfono su Android durante il riconoscimento; interruzione a voce solo con cuffie misurate o AEC di sistema (`echoCancellation: { ideal: "all" }`).
- **Animazione del parlato.** `onboundary` quando c'è, altrimenti orologio stimato con snap e calibrazione per voce; la diagnostica dice quale. Ogni segmento appare intero a bassa opacità appena chiuso nel JSON e si inchiostra parola per parola.
- **Didattica.** Una sola riga corretta per turno con ≤ 2 modifiche, diff calcolato dall'app da `heard`/`correct`; la ripetizione non è mai votata, la produzione guidata alla battuta successiva sì; schede errore create dall'app per chiave normalizzata alla seconda ricaduta (alla prima se compromettono la comprensione). Fasi di sessione (`phase`, `elapsed_s`, `beats_done`) decise dall'app e passate nella scheda; chiusura "tre cose" quando il tempo supera l'obiettivo meno 90 s o l'ultima battuta è completata. FSRS: `request_retention 0.9`, `maximum_interval 180`, `enable_fuzz`, `enable_short_term`, `learning_steps ["2m","8m"]`, `relearning_steps ["5m"]`; stato ricalcolato dal registro dei ripassi; FAILED → Again sempre. Peso e opacità delle righe della stoffa derivano dallo stato FSRS.
- **Dati.** IndexedDB con registro eventi append-only `(device_id, seq, ts, id)` + snapshot, replay deterministico, compattazione con `compacted_until` per dispositivo; export/import JSON; sync con repo privato GitHub via Contents API (`GET` con `If-None-Match` e `cache: "no-cache"`, `PUT` con `sha`, 409 → rileggi/riunisci/riprova max 5, 422 → nessun retry, `Retry-After` rispettato; `GET` all'avvio, `PUT` a fine turno con debounce 10 s, a fine sessione e su `visibilitychange`; file mensili). Nessun `X-GitHub-Api-Version` dal browser.
- **Pages/PWA.** `base: '/english-vera/'`, nessun routing per percorso; deploy via Actions (`configure-pages`, `upload-pages-artifact`, `deploy-pages`); `registerType: 'prompt'` con aggiornamento applicato solo nello stato Riposo; `injectRegister: null`; Workbox non mette mai in cache le API; Media Session spenta su iOS.
- **Design.** Token su `:root`, tema scuro sotto `prefers-color-scheme` e `[data-theme]`, `body` con sfondo esplicito; solo `transform`/`opacity` in animazione; `prefers-reduced-motion` rispettato con stati distinguibili dalla sola geometria; il colore di correzione compare solo per errori linguistici, mai per errori di sistema; etichetta di stato ≥ 20 px su telefono; ordito sopra il testo solo nei margini; registro "documento istituzionale futuristico": carta fredda, grafite, una tinta di segnaletica, niente lino o cuciture; Archivo (inglese e interfaccia; alternativa da provare: Public Sans) + Source Serif 4 corsivo (italiano), da confermare con la "prova brutale" del traguardo 1; palette in `docs/PIANO.md` §1.7; modalità tasca solo con entrata esplicita.

## Cosa funziona / cosa non è verificato (aggiornare a ogni sessione)

- Funziona (verificato con test): giro completo in modalità testo (con la voce di Vera) e con motori vocali finti; streaming della risposta strutturata con voce al primo segmento; una utterance alla volta; «Ripeti» mentre Vera parla ricomincia la risposta corrente e riapre il microfono; riapertura del microfono nella lingua chiesta da Vera; primo turno di Vera senza aprire il microfono prima del saluto, in entrambe le modalità di ascolto; retry automatico su 429 con conto alla rovescia; primo avvio senza chiave che porta alla sezione Chiave; stoffa che scorre al suo interno sul telefono con soglia e aiuti sempre visibili; cache della storia (breakpoint sull'ultimo messaggio della storia); costo da `usage` (anche parziale); etichetta copiabile senza segreti con i provini delle voci; tema scuro; movimento ridotto; layout telefono e desktop (screenshot).
- Non verificabile da questa macchina: audio reale, voci reali e boundary, comportamento su telefoni veri (bip Android, ascolto nell'app installata su iPhone, permessi), latenza reale dei modelli e confronto dei preset (la diagnostica mostra i tempi: l'utente li legge dall'etichetta), qualità didattica del prompt su turni reali, `PUT` reale sulla Contents API dall'origine Pages.
- Resta all'utente: attivare GitHub Pages (Source = GitHub Actions) e chiedere la pull request verso `main` (o autorizzare il branch di lavoro); creare la chiave API con limite di spesa; non pubblicare altri siti Pages sullo stesso account; fare la "prova del telefono" (`#prova` o Etichetta > Dati) su entrambi i telefoni e incollare l'esito; (traguardo 4) repo privato + token per la sync.
